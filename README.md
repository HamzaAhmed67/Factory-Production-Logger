# مسجّل العمليات والإنتاج الصناعي - UG Enterprise Production ERP

نظام متكامل وخفيف وسريع لإدارة وتوثيق عمليات الإنتاج اليومية على خطوط المصانع، وإدارة مهام العمال، وتوثيق بصمات السهر والورديات الإضافية، مع لوحات تحكم حية للمشرفين والإدارة، ودعم كامل للغتين **العربية (RTL)** و**الإنجليزية (LTR)** والوضعين **الفاتح (Light Mode)** و**الداكن (Dark Mode)**.

---

## 🌟 أبرز المميزات والإضافات الجديدة (Key Features)

### 🔐 1. نظام الصلاحيات والأدوار (Role-Based Access Control - RBAC)
يوفر النظام بوابات مخصصة بثلاثة مستويات وصول دقيقة:
* **عامل (Worker)**:
  - واجهة مبسطة خالية من التعقيد تركز على تنفيذ أوامر الشغل الموكلة إليه أو تسجيل مهام جديدة.
  - **دورة العمل ثلاثية المراحل غير القابلة للعكس (Irreversible 3-Stage Lifecycle)**:
    1. `قيد الانتظار (Pending)` ⏳
    2. `قيد التنفيذ (In Progress)` 🚀 (توثيق وقت البدء تلقائياً)
    3. `مكتمل (Completed)` ✅ (توثيق وقت الانتهاء وحساب مدة الإنجاز)
  - دعم إدخال الأوزان والكميات بمختلف الوحدات (`كجم / kg` أو `جرام / g` أو وحدات عددية).
* **مشرف إنتاج (Supervisor)**:
  - لوحة تحكم تفاعلية لمتابعة العمليات ومؤشرات الأداء اللحظية (KPIs).
  - **تكليف وتوزيع أوامر الشغل (Job Order Dispatch)** وتعيينها لعمال محددين مع تحديد المنتج والوزن والوحدة.
  - متابعة وتصفية سجلات الإنتاج وسجلات بصمة السهر.
  - تصدير التقارير بجميع الصيغ (Excel / PDF / JSON).
  - حماية إدارية: إخفاء لوحة إدارة الحسابات وكلمات المرور عن المشرفين لقصرها على المدير العام فقط.
* **مدير النظام (Admin)**:
  - جميع صلاحيات المشرفين بالإضافة إلى تبويب **إدارة المستخدمين (User Management)** لتعديل بيانات الموظفين، الأدوار، وتحديث كلمات المرور.

---

### 🌙 2. بوابة بصمة السهر والورديات الإضافية (Overtime Portal)
- بوابة مخصصة لتسجيل حضور وانصراف السهر والورديات الليلية للعمال.
- توثيق دقيق لاسم العامل، التاريخ، الوقت بالثانية، وملاحظات الوردية.
- تبويب منفصل في لوحة الإدارة لمراجعة وتصفية وحذف سجلات السهر وتصديرها.

---

### 📊 3. مؤشرات الأداء الحية والتحليلات (Real-Time KPIs)
- بطاقات إحصائية عالية التباين والوضوح لحساب:
  - **إجمالي الإنتاج (Total Volume)** بالكيلوجرام والجرام.
  - **المهام المكتملة (Completed Orders)** ومعدلات الإنجاز.
  - **المهام الجارية وقيد الانتظار (In-Progress & Pending)**.
  - **العمال النشطين (Active Workforce)** خلال الوردية.

---

### 📑 4. تصدير التقارير متعدد الصيغ (Multi-Format Exports)
- **Microsoft Excel (CSV مع UTF-8 BOM)**: لضمان فتح الجداول باللغة العربية داخل Excel دون أي تشويه في الحروف أو الترميز.
- **طباعة تقارير رسمية (Printable PDF View)**: تصميم أنيق لطباعة تقارير الورديات والإحصائيات.
- **تصدير بيانات JSON**: للتكامل والأرشفة الرقمية.

---

### 🛡️ 5. تخزين مزدوج موثوق بدون توقف (Zero-Downtime Dual Storage)
- **MongoDB**: اتصال مرن عبر Mongoose مع تهيئة الحسابات الافتراضية تلقائياً.
- **Local JSON Storage Fallback**: في حال توقف خدمة MongoDB أو انقطاع الاتصال بقاعدة البيانات، ينتقل النظام تلقائياً وبسلاسة إلى التخزين المحلي في ملف (`data/production_data.json`) دون أي تعطل أو فقدان للبيانات.

---

### 🎨 6. الهوية البصرية وتجربة المستخدم (Design & UX)
- **الوضع الفاتح (Light Mode)**: خلفية مريحة للعين بدرجة الرمل الدافئ (`#d9bda5`) وبطاقات زجاجية فاخرة.
- **الوضع الداكن (Dark Mode)**: خلفية من حجر الأوبسيديان الداكن مع لمسات كحلية وذهبية متألقة.
- **تباين ونقاء بصري فائق**: نصوص وبطاقات واضحة وعالية المقروئية على جميع الشاشات.
- **دعم الأجهزة اللوحية والمحمولة**: تصميم متجاوب بالكامل لشاشات اللمس وأجهزة التابلت المستخدمة في أرض المصنع.
- **تطبيع الأرقام العربية**: قبول الأرقام المشرقية (`١٢٣`) والغربية (`123`) بسلاسة تامة أثناء تسجيل الدخول.
- **واجهة تسجيل دخول آمنة ونظيفة**: مجهزة للإنتاج مع إخفاء أي بيانات تجريبية سابقة.

## 🚀 التشغيل والتثبيت (Getting Started)

### المتطلبات
- **Node.js** (v18+)
- **MongoDB** (اختياري - يعمل محلياً أو سحابياً، مع وجود بديل التخزين التلقائي)

### خطوات التشغيل

1. **تثبيت الاعتماديات**:
   ```bash
   npm install
   ```

2. **ضبط ملف البيئة (`.env`)**:
   انسخ ملف `.env.example` إلى `.env`:
   ```env
   PORT=3000
   MONGODB_URI=mongodb://localhost:27017/factory_production
   ```

3. **تشغيل الخادم**:
   - وضع الإنتاج (Production):
     ```bash
     npm start
     ```
   - وضع التطوير مع التحديث التلقائي (Dev Watch Mode):
     ```bash
     npm run dev
     ```

4. **تشغيل الاختبارات الآلية (Automated Tests)**:
   ```bash
   npm test
   ```

5. افتح المتصفح على:
   ```
   http://localhost:3000
   ```

## 📡 مسارات الواجهة البرمجية (API Reference)

| المسار (Endpoint) | الطريقة (Method) | الوصف (Description) |
| :--- | :---: | :--- |
| `/api/health` | `GET` | فحص حالة الخادم ونوع التخزين النشط (MongoDB أم التخزين المحلي) |
| `/api/auth/login` | `POST` | تسجيل دخول الموظفين (عمال، مشرفين، إدارة) مع التحقق من الصلاحيات |
| `/api/logs` | `GET` | جلب جميع سجلات الإنتاج مرتبة تنازلياً |
| `/api/logs` | `POST` | إضافة سجل إنتاج جديد أو تكليف أمر شغل جديد |
| `/api/logs/:id/status` | `PATCH` | تحديث حالة أمر الشغل (`pending` ➔ `in_progress` ➔ `completed`) وتوثيق الوقت |
| `/api/logs/:id` | `DELETE` | حذف سجل إنتاج محدد (للمشرفين والإدارة) |
| `/api/overtime` | `GET` | جلب سجلات بصمة السهر والورديات الإضافية |
| `/api/overtime` | `POST` | تسجيل حضور سهر جديد لعامل |
| `/api/overtime/:id` | `DELETE` | حذف سجل بصمة سهر |
| `/api/users` | `GET` | استعراض حسابات الموظفين ومسمياتهم الوظيفية (خاص بالمدير) |
| `/api/users/:username` | `PUT` | تعديل بيانات مستخدم أو تغيير كلمة المرور أو الدور |
